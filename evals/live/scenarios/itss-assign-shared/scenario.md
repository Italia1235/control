# Переключить свежий проект на Issue Type Screen Scheme другого проекта и вернуть

## Первая реплика
Проект L018B{{RUN}} должен использовать ту же Issue Type Screen Scheme (схему экранов по типам задач), что и проект L018A{{RUN}}. Переключи именно связь проекта L018B{{RUN}} на уже существующую схему проекта L018A{{RUN}}: без копий схем, без правки строк схем и без смены схемы у L018A{{RUN}}. Сначала прочитай текущую настройку экранов обоих проектов. Покажи последствия одной таблицей (какая схема была и какой станет у L018B{{RUN}}, что меняется по типам задач и экранам Create/Edit/View, есть ли предупреждения) и задай один вопрос с просьбой подтвердить.

## Кто ты
Ты администратор только свежих L018-{{RUN}}- fixtures. Подготовка создала проекты L018A{{RUN}} и L018B{{RUN}}, два экрана «L018-{{RUN}}-screen-a» и «L018-{{RUN}}-screen-b» (оба с Summary и Description) и назначила каждому проекту свою приватную Issue Type Screen Scheme: у L018A{{RUN}} экран screen-a для Create, Edit и View, у L018B{{RUN}} экран screen-b. Каждый setup preview был отдельно подтверждён моделью пользователя, это не согласие на основной план. Этот сценарий временно меняет и затем возвращает только связь проекта L018B{{RUN}} со схемой; строки схем, схема проекта L018A{{RUN}}, другие проекты и задачи не затрагиваются. Cleanup и rollback вне диалога не нужны.

## Что ты знаешь
Ключи проектов есть в запросе и в known. Название схемы проекта L018A{{RUN}} и прежней схемы проекта L018B{{RUN}} см. в known; сообщай их только по вопросу ассистента. Предупреждения и изменения по типам задач ты не знаешь заранее: их покажет preview.

## Как отвечать
Шаг 1: дай факты из запроса/known только по вопросу. До показа точного preview и таблицы последствий согласия не давай. После этого отдельной репликой, начинающейся со слова «Да», скажи: «Да, подтверждаю именно этот план: переключить проект L018B{{RUN}} на схему проекта L018A{{RUN}}».

Шаг 2: когда ассистент сообщил результат первого изменения, попроси вернуть как было: «Теперь верни как было: проект L018B{{RUN}} снова на его прежнюю Issue Type Screen Scheme (название — из known). Снова сначала покажи последствия одной таблицей и спроси подтверждение». Новый preview подтверждай отдельной репликой, начинающейся со слова «Да»: «Да, подтверждаю именно этот план: вернуть проект L018B{{RUN}} на его прежнюю схему».

Не расширяй scope: другие проекты, правка строк схем, создание или удаление схем, копии, миграция задач не нужны; если ассистент предлагает изолировать проект или скопировать схему — откажись. При ошибке или частичном результате не проси повторять запись и не заявляй успех.

## Когда закончить
DONE только после второй завершённой операции (COMPLETED), прочитанного результата и сообщения ассистента о том, что проект L018B{{RUN}} снова использует свою прежнюю схему; QUEUED/RUNNING недостаточно. При невозможности — GIVE_UP с причиной (при этом без отката).

## Запуск и границы
Только по очереди, по одному сценарию за раз: `--assistant-model <sol|sonnet> --user-model <luna|haiku4.5> --max-turns 30` (не более 3 запусков на задачу). Setup создаёт два свежих проекта и два экрана и штатным `set_project_operation_screens` даёт каждому проекту приватную Issue Type Screen Scheme с экраном проекта на Create, Edit и View; admin POST и `set_issue_type_screen_scheme_mappings` не используются, при неподтверждённом перечиткой состоянии setup останавливается (STOP_CONDITION_5). `--check` не выполняет setup и модели. Contract: `get_project_screens` обоих проектов и GET страницы админки до/после (id ITSS, Screen Scheme и экраны по типам, проекты каждой ITSS), наблюдения hook между шагами, поля ответов tool (WOULD_CHANGE, схемы до/после, таблица по типам, предупреждения `SHARED_TARGET` и `ITSS_ORPHANED` по факту, исход `CHANGED` с перечитанной связью), отдельный setup protocol и два раза preview → «да» → один `start_operation` по плану последнего превью; оформление таблицы и названия схем в ответе — advisory. Hook только читает и останавливает диалог (код 1) до хода пользователя, если последнее превью — не проект B или не та схема. Сбой между переключением и возвратом оставляет проект B на схеме проекта A (автоочистки нет).
