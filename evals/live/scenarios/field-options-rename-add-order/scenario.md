# Переименование, добавление и порядок опций существующего контекста одним согласием

Подготовка и проверки полностью автоматические: `setup.mjs` создаёт проект {{NAME:proj}} ({{KEY:proj}}) и поле «Приоритет {{RUN}}» (список) с контекстом «Основной» для этого проекта и всех типов задач. Опции по порядку: «Низкий», «Средний», «Высокий». Ручная подготовка в Jira не нужна. Созданные объекты остаются после прогона.

## Кто ты

Администратор Jira, не разработчик. Не знаешь названий инструментов и API, не диктуешь ассистенту вызовы. Не видишь tools и результаты проверок runner; не выдавай ожидаемое поведение за свои наблюдения.

## Первая реплика

В поле «Приоритет {{RUN}}» переименуй «Средний» в «Нормальный», добавь опцию «Срочный» и поставь «Высокий» первым в списке.

## Что ты знаешь (говори только когда ассистент спросит)

- Изменения нужны только в списке опций контекста «Основной» этого поля; проекты, типы задач, значение по умолчанию и сами задачи менять не нужно.
- Новая опция «Срочный» должна быть включена. Порядок остальных: «Высокий», «Низкий», «Нормальный»; «Срочный» может оказаться последним — это нормально.
- Ничего не нужно удалять или отключать.

## Как себя вести

1. До показанного плана ничего не подтверждай. План должен быть одним на все три изменения: переименование, добавление и порядок. Если ассистент предлагает три отдельных подтверждения, попроси показать всё одним планом.
2. Когда увидишь одну таблицу «было → стало» и последствия переименования (отображение у всех задач и фильтры), ответь отдельной репликой: «Да, применяй». Не совмещай согласие с первой просьбой.
3. Если ассистент спрашивает то, что ты уже сказал, ответь коротко ещё раз. Не придумывай результатов проверок в Jira.
4. Если ассистент предлагает удалить опцию или изменить задачи — откажись.

## Когда заканчивать

- DONE — ассистент сообщил, что опции изменены: «Высокий», «Низкий», «Нормальный», «Срочный».
- GIVE_UP — три неудачных попытки или хождение по кругу. Честно сообщённый отказ не превращай в успех.

## Автоматические критерии приёмки

- Опции прочитаны через `get_field_contexts` с `includeOptions=true` до превью; в превью используются только возвращённые optionId.
- Ровно одно превью `update_field_contexts` только с `options` (без осей области): `rename` «Средний» → «Нормальный», `add` «Срочный», `order` из трёх существующих опций верхнего уровня; ответ показан одной таблицей и одним вопросом; planId пользователю не показан.
- Один `start_operation` по planId этого превью в ходе после «Да»; результат `UPDATED`, без отдельных подтверждений на части.
- По живому чтению порядок «Высокий», «Низкий», «Нормальный», «Срочный», все опции включены, идентификаторы исходных опций, контекста и конфигурации сохранены.
