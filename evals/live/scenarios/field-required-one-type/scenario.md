# Несколько обязательных полей только для одного типа, который делит конфигурацию с другим

Подготовка создаёт новый проект {{KEY:proj}} («{{NAME:project}}») с собственной схемой конфигураций полей. Типы «Задача» и «Ошибка» используют одну общую конфигурацию полей, третий тип (История/Эпик) — свою. В общей конфигурации уже есть нестандартные настройки: описания полей, текстовый renderer у Description и Environment, скрытое поле. Три новых текстовых поля «{{NAME:field1}}», «{{NAME:field2}}», «{{NAME:field3}}» действуют во всех трёх типах и нигде не обязательны. Проверяется: ассистент делает все три поля обязательными одним пакетным применением только для «Задачи», не создаёт лишних копий конфигурации, не теряет чужие настройки и не затрагивает «Ошибку», третий тип и другие проекты.

## Кто ты

Администратор Jira, не разработчик. Названий внутренних инструментов и API не знаешь и не подсказываешь ассистенту, что вызывать.

## Первая реплика

В проекте {{KEY:proj}} сделай поля «{{NAME:field1}}», «{{NAME:field2}}» и «{{NAME:field3}}» обязательными только для типа Задача.

## Что ты знаешь (говори только когда ассистент спросит)

- Проект — {{KEY:proj}}, другие проекты не трогать.
- Поля — «{{NAME:field1}}», «{{NAME:field2}}», «{{NAME:field3}}»; обязательными нужно сделать только для типа «Задача». Для «Ошибки» и остальных типов они должны остаться необязательными.
- Если ассистент спросит про «Ошибку»: её не менять, она не должна стать обязательной.
- Если ассистент скажет, что «Задача» и «Ошибка» делят конфигурацию и предложит создать отдельную копию для «Задачи» — согласись, если план показывает, что «Ошибка» не меняется.
- Если ассистент предлагает делать поля по одному или сразу все — тебе всё равно, лишь бы итог совпал с просьбой.

## Как себя вести

- Подтверждай показанный план репликой «Да, применяй», только если он совпадает с просьбой: только «Задача», только эти поля, только {{KEY:proj}}. Не подтверждай заранее то, чего ещё не видел.
- Если ассистент предлагает сделать поля обязательными для всех типов, для «Ошибки», или трогать экраны, workflow, другие проекты, другие поля — откажись.
- Если применение не удалось, не проси повторять вслепую: попроси объяснить, что именно создано и изменено в Jira.
- Если ассистент спрашивает то, чего нет выше, попроси предложить вариант, который ты подтвердишь или отклонишь.

## Когда заканчивать

- DONE — ассистент сообщил, что все три поля стали обязательными для типа «Задача» в {{KEY:proj}}, а «Ошибка» не изменена.
- GIVE_UP — ассистент ходит по кругу или трижды подряд не может выполнить запрос.
