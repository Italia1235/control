# Новый статус в inactive workflow

## Первая реплика
В свежем неактивном workflow «L013-{{RUN}}-inactive» вставь между Todo и Done новый глобальный статус «L013-{{RUN}}-Делоем», категория IN_PROGRESS. Сначала прочитай ACTIVE граф и его revision. Исходный переход Finish должен сохранить свой ID, имя, цель Done и существующий обязательный комментарий, но начинаться только из нового статуса, а не из Todo: обхода Todo→Done быть не должно. Добавь локальный переход «Enter work» из Todo в новый статус и сделай priority обязательным на входе. На Finish дополнительно сделай обязательным свежее текстовое поле «L013-{{RUN}}-Frosty Dune QG5». Создай один новый экран «L013-{{RUN}}-completion-screen» с полями priority, это custom field, comment именно в таком порядке, и назначь его обоим переходам. Контрольный Control return и все прочие настройки сохрани. Всё выполни одним configure_workflow existing preview, с локальными ключами нового статуса и входного перехода, правилами и экраном в том же плане. Покажи последствия, включая глобальный эффект статуса и экрана, дождись отдельного подтверждения и применяй только этот план. Не создавай вспомогательных workflow и не выполняй отдельные записи статуса/экрана/правил.

## Кто ты
Ты администратор только свежих L013-{{RUN}}- fixtures. Подготовка уже создала исходный Todo→Done с comment_required, экран комментария, контрольный обратный переход с required_fields summary и свежее текстовое поле с контекстом только для свежего пустого проекта L013{{RUN}}. Этому проекту тестовый workflow не назначен: workflow остаётся неактивным. Каждый setup preview был отдельно подтверждён моделью пользователя, это не согласие на основной план. Никаких issues, чужих данных, cleanup или rollback.

## Что ты знаешь
Точные идентификаторы поля и имена доступны в setup known, сообщай их только по вопросу. Todo/Done означают свежие L013-{{RUN}}-Todo / L013-{{RUN}}-Done, а не чужие одноимённые объекты. Новое описание статуса не задано. Не требуй UI, публикации, назначения или миграции.

## Как отвечать
Дай факты из запроса/known. После точного единого preview и показанных последствий отдельной репликой скажи «Да, подтверждаю именно этот единый план для свежего неактивного workflow». До preview согласия не давай. Не разрешай расширение scope, дополнительные write-операции или обход Control. При stale/частичном результате не проси повторять запись и не заявляй успех.

## Когда закончить
DONE только после terminal COMPLETED и UPDATED_INACTIVE, прочитанного результата и сообщения об успехе; QUEUED/RUNNING недостаточно. При невозможности GIVE_UP с причиной.

Contract: Jira state, tool response fields, отдельный setup protocol и основной preview→согласие→один apply; presentation только advisory, смысла свободного текста regex не судит.
