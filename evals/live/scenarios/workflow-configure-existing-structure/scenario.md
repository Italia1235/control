# Existing structure, new local transition + screen + validator

## Первая реплика
В свежем тестовом неактивном workflow «L012-{{RUN}}-structure» переименуй «Start work» в «Started». Одновременно добавь локальный переход «Complete» из «L012-{{RUN}}-Working» в «L012-{{RUN}}-Done» с Resolution из существующего справочника (уточни у меня значение). Для нового перехода создай новый экран «L012-{{RUN}}-completion-screen» с полями Summary и Assignee, именно в этом порядке, и назначь его этому переходу. При выполнении «Complete» валидатор должен требовать заполненного Assignee; других валидаторов и условий доступа не добавляй. Обе правки workflow, создание и назначение экрана и добавление валидатора выполни одной общей операцией, без промежуточных сохранений. Переход «Control return», остальные существующие переходы и статусы не менять. Сначала прочитай текущее состояние workflow, покажи общий план с последствиями и дождись моего отдельного подтверждения. Никакой публикации или назначения проекту.

## Кто ты
Ты администратор, проверяющий только свежие объекты этого прогона. Подготовка уже создала workflow и три новых статуса L012-{{RUN}}-Todo / Working / Done. Чужие объекты менять нельзя.

## Что ты знаешь
- Из setup known тебе доступны канонические ID и имя Resolution. По вопросу назови именно это существующее значение; не придумывай другое.
- Новые имена и поля заданы точно; обязательность Assignee нужна только на переходе, не в конфигурации полей проекта.
- Не соглашайся на несколько планов вместо одной общей операции. Отдельное создание экрана, публикация, назначение workflow проекту и любые посторонние изменения не разрешены.

## Как отвечать
Когда ассистент покажет точный общий preview с нужными объектами и последствиями, ответь отдельной репликой «Да, подтверждаю этот общий план». До этого не давай согласия. На уточнение отвечай фактами выше/known. Если ассистент предлагает иной scope, попроси вернуться к запросу, не разрешай обходы.

## Когда закончить
DONE только когда ассистент дождался terminal success и сообщил об обеих правках, новом экране и валидаторе. QUEUED/RUNNING не конец. Если выполнить нельзя, GIVE_UP с причиной; не изображай успех.
