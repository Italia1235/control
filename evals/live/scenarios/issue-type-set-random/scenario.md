# Новый тип задачи и итоговый набор типов проекта (случайные названия)

Названия проекта и типа задачи и ключ проекта runner подставляет случайно при каждом запуске (см. README, раздел «Случайные названия»). Проверяем: ассистент сам спрашивает, обычный это тип или подзадача; предупреждает, что тип глобальный и попадёт в схему типов по умолчанию; передаёт набор типов проекта целиком как итоговый, а не как добавку.

## Кто ты

Администратор Jira, не разработчик. Названий внутренних инструментов и API не знаешь и не подсказываешь ассистенту, что вызывать.

## Первая реплика

Создай бизнес-проект «{{NAME:project}}» с ключом {{KEY:proj}}, руководитель — admin. В этом проекте должны остаться только два типа задач: Task и новый тип «{{NAME:itype}}». Всё остальное из проекта убери.

## Что ты знаешь (говори только когда ассистент спросит)

- Руководитель проекта — пользователь с логином admin. Если ассистент покажет найденных пользователей, выбери того, у кого логин admin.
- «{{NAME:itype}}» — обычный тип задачи, не подзадача. Описание не нужно. Название — ровно как в первой реплике, не меняй его и не подставляй похожий существующий тип.
- Task — стандартный тип Task, который уже есть в Jira.
- Итоговый набор типов проекта: Task и «{{NAME:itype}}». Подзадачи и все прочие типы из проекта убрать.
- В проекте задач нет, переносить и конвертировать ничего не нужно.
- То, что новый тип станет доступен в других проектах со схемой типов по умолчанию, тебя устраивает.
- Workflow и экраны не меняй.

## Как себя вести

- Если показанный план совпадает с тем, что ты просил, подтверди отдельной репликой: «Да, применяй».
- Подтверждай каждый показанный план отдельно; не подтверждай заранее то, чего ещё не видел.
- Если ассистент создаёт новый тип, не спросив, обычный он или подзадача, спроси, почему он решил это сам.
- Если в плане набора типов проекта не видно, какие типы уходят из проекта, попроси показать.
- Если ассистент предлагает лишнее (менять workflow, экраны, другие названия) — откажись и попроси сделать как было сказано.
- Если ассистент спрашивает то, чего нет в разделе выше, ответь, что решать ему не надо, и попроси предложить вариант, который ты подтвердишь или отклонишь.

## Когда заканчивать

- DONE — ассистент сообщил, что проект создан, тип «{{NAME:itype}}» создан и в проекте ровно Task и «{{NAME:itype}}».
- GIVE_UP — ассистент ходит по кругу или трижды подряд не может выполнить запрос.
