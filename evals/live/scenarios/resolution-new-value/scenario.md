# Workflow с новым и неоднозначным Resolution (случайные названия)

Название workflow runner подставляет случайно при каждом запуске (см. README, раздел «Случайные названия»); `{{RUN}}` в названии нового Resolution не даёт повторному прогону упереться в значение прошлого. Проверяем:

- ассистент сначала смотрит существующие Resolution и не создаёт новое значение, если подходит существующее;
- «сделано» не превращается молча в Fixed: ассистент выбирает существующее значение по смыслу или спрашивает;
- перед созданием Resolution ассистент предупреждает, что значение глобальное для всей Jira, а не только для этого workflow;
- создание Resolution и создание workflow подтверждаются отдельно; после создания Resolution план workflow строится заново с его настоящим ID.

Прогон создаёт глобальный Resolution, очистки нет.

## Кто ты

Администратор Jira, не разработчик. Названий внутренних инструментов и API не знаешь и не подсказываешь ассистенту, что вызывать.

## Первая реплика

Создай workflow «{{NAME:wf}}»: Open → Review → Approved, и из Review переход «Reject» в статус Rejected. При одобрении ставь резолюцию «сделано», а при Reject — новую резолюцию «Rejected by Client {{RUN}}», её в Jira пока нет.

## Что ты знаешь (говори только когда ассистент спросит)

- Начальный статус — Open. Категории: Open — «К выполнению», Review — «В работе», Approved и Rejected — «Выполнено». Если такие статусы уже есть в Jira — используй существующие.
- Переходы: Open → Review «Send to Review», Review → Approved «Approve», Review → Rejected «Reject». Других переходов не нужно.
- «Сделано» — это существующая резолюция Done. Если ассистент покажет варианты, выбери Done; если Done в Jira нет, выбери Fixed. Новую резолюцию «Сделано» не создавать.
- «Rejected by Client {{RUN}}» — новая резолюция, ровно такое название, описание не нужно. То, что она будет доступна во всей Jira, тебя устраивает.
- Экраны на переходах не нужны.
- Только создать workflow, ни к какому проекту не назначать.

## Как себя вести

- Если показанный план совпадает с тем, что ты просил, подтверди отдельной репликой: «Да, применяй».
- Подтверждай каждый показанный план отдельно; не подтверждай заранее то, чего ещё не видел.
- Если ассистент предлагает создать новую резолюцию вместо «сделано» — откажись: нужна существующая.
- Если ассистент предлагает создать «Rejected by Client {{RUN}}», не предупредив, что она появится во всей Jira, — спроси, где она будет доступна, и подтверждай только после ответа.
- Если ассистент предлагает заменить «Rejected by Client {{RUN}}» существующей резолюцией (например Won't Do) — откажись: нужна именно новая.
- Если ассистент предлагает лишнее (назначить на проект, добавить экраны, другие названия) — откажись и попроси сделать как было сказано.
- Если ассистент спрашивает то, чего нет в разделе выше, ответь, что решать ему не надо, и попроси предложить вариант, который ты подтвердишь или отклонишь.

## Когда заканчивать

- DONE — ассистент сообщил, что резолюция «Rejected by Client {{RUN}}» и workflow созданы, Approve ставит Done (или Fixed), Reject — новую резолюцию.
- GIVE_UP — ассистент ходит по кругу или трижды подряд не может выполнить запрос.
