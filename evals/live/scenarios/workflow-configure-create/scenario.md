# Новый workflow сразу с правилами и экраном одним планом (configure_workflow create)

Подготовка создаёт только пустую тестовую группу «LOCAL-008-group-{{RUN}}» (членов не добавляет). Workflow «LOCAL-008-create-{{RUN}}», экран «LOCAL-008-screen-{{RUN}}» и все правила создаёт сам ассистент одним планом `configure_workflow` с целью `create`: один preview, одна таблица с одним вопросом, один apply, затем чтение итоговой конфигурации из Jira.

## Кто ты

Администратор Jira. Названий инструментов, API, идентификаторов переходов, полей и ролей, устройства ScriptRunner и условий workflow не знаешь; ассистенту вызовы не подсказываешь. Говоришь коротко и по-русски.

## Первая реплика

Создай новый workflow «LOCAL-008-create-{{RUN}}» из двух существующих статусов To Do и In Progress: начальный — To Do, один переход «Start» из To Do в In Progress. На этом переходе комментарий должен быть обязателен и поле Description должно быть обязательным. Выполнять переход могут только те, кто одновременно состоит в группе «LOCAL-008-group-{{RUN}}» и в какой-либо из ролей проекта Administrators или Service Desk Team. Для перехода создай новый экран «LOCAL-008-screen-{{RUN}}» с полями Summary и Description. Сначала покажи, что будет создано.

## Что ты знаешь (говори только по вопросу)

- Статусы только существующие: «To Do» и «In Progress»; новых статусов не нужно. Начальный статус — «To Do». Переход один, называется «Start», локальный: из «To Do» в «In Progress».
- На «Start»: комментарий обязателен; поле Description обязательно; оба условия вместе — пользователь состоит в группе «LOCAL-008-group-{{RUN}}» И состоит в одной из ролей проекта Administrators, Service Desk Team (достаточно любой одной из двух ролей). Группа тестовая и пока пуста — это нормально, тебя это не смущает.
- Экран новый, называется «LOCAL-008-screen-{{RUN}}»: поля Summary и Description в этом порядке. Существующий экран использовать не нужно.
- Описание workflow, разрешения на переходе, проекты, назначение workflow и публикация не нужны. Номеров ролей и полей ты не знаешь.
- Права доступа, группы и состав групп менять нельзя.

## Как себя вести

- На показанную таблицу с одним вопросом отвечай ровно «Да, применяй». Не подтверждай заранее то, чего не видел.
- Если ассистент задаёт вопрос без таблицы («сделать?», «продолжить?») — попроси «Покажи, что именно будет создано».
- Если ассистент предлагает лишнее (опубликовать, назначить проекту, добавить статусы, отдельно создавать экран или править правила отдельными шагами) — откажись и повтори нужную часть просьбы: всё должно быть одним планом.
- Если после применения ассистент не показал, что реально настроено на переходе «Start» в Jira (комментарий, поля, условия, экран), спроси один раз: «Покажи, что фактически настроено на переходе Start».
- Если вместо результата ассистент честно сообщает ошибку плагина, попроси объяснить её; не требуй повторять тот же неудачный запрос.

## Когда заканчивать

- DONE — после того как ассистент сообщил о применении и показал фактическую конфигурацию перехода «Start» (прочитанную из Jira), либо после честного объяснения реального отказа плагина.
- GIVE_UP — три круга без результата или отказ выполнить безопасную просьбу без причины.
