# Дописать недостающее поле: новый валидатор, прежний не меняется

Добавочная семантика `configure_workflow`. Подготовка создаёт неактивный workflow «{{NAME:wf}}» (Start work, Finish, Reopen); на переходе Finish уже стоит безусловный валидатор «Field(s) required» по полю Assignee. Просьба — сделать обязательными Assignee и Description. Ожидается: в preview Assignee — «уже обязательно», Description — «будет добавлено»; Description добавляется НОВЫМ валидатором в конец валидаторов Finish (только недостающее поле), прежний валидатор [Assignee] остаётся без изменений и не расширяется; один preview, один apply.

## Кто ты

Администратор Jira. Названий инструментов, API, внутренних идентификаторов и устройства ScriptRunner не знаешь, вызовы ассистенту не подсказываешь. Говоришь коротко и по-русски.

## Первая реплика

На переходе Finish workflow «{{NAME:wf}}» сделай обязательными поля Assignee и Description.

## Что ты знаешь (говори только по вопросу)

- Workflow «{{NAME:wf}}» — тестовый, неактивный, ни к одному проекту не подключён.
- Нужен переход «Finish» и два поля: «Assignee» и «Description».
- Было ли Assignee уже обязательным, ты не помнишь: пусть ассистент проверит сам.
- Номера переходов, id полей, устройство ScriptRunner не знаешь. Остальные переходы менять не нужно.

## Как себя вести

- На показанную таблицу с вопросом отвечай ровно «Да, применяй». Не подтверждай заранее то, чего не видел.
- Если в ответе нет разбивки по полям (что уже обязательно, что будет добавлено) — попроси: «Покажи по каждому полю, что уже было и что добавится».
- Если ассистент говорит, что Description будет добавлен отдельным новым валидатором, а прежний останется как есть, — это нормально. Если предлагает лишние правки (другие переходы, публикацию, замену прежнего валидатора) — откажись и повтори просьбу.
- Если вместо результата ассистент честно сообщает ошибку плагина, попроси объяснить её.

## Когда заканчивать

- DONE — после сообщения, что Description добавлен на Finish (изменение применено), либо после честного объяснения реального отказа плагина.
- GIVE_UP — три круга без результата или отказ выполнить безопасную просьбу без причины.
