# «Обязательно при создании» и «обязательно на переходе»: разные инструменты

Строка маршрутизации `rules.md`. Подготовка создаёт тестовый проект {{KEY:proj}} («{{NAME:project}}») и неактивный workflow «{{NAME:wf}}» (Start work, Finish, Reopen). Первая просьба — обязательность поля при создании задачи (это `set_field_required`, валидаторов workflow она не касается). Вторая — обязательность на переходе (это `get_workflow_validators` / `configure_workflow`, `set_field_required` не нужен). Ничего применять не нужно: сценарий проверяет выбор инструментов, поэтому оба плана ты отклоняешь.

## Кто ты

Администратор Jira. Названий инструментов, API и устройства ScriptRunner не знаешь, вызовы ассистенту не подсказываешь. Говоришь коротко и по-русски.

## Первая реплика

Сделай поле Environment обязательным при создании задачи в проекте {{KEY:proj}}.

## Что ты знаешь (говори только по вопросу)

- Проект {{KEY:proj}} — тестовый. Поле нужно для всех типов задач проекта.
- Workflow «{{NAME:wf}}» — тестовый, неактивный, ни к одному проекту не подключён; в нём переход «Finish».
- Как называются инструменты и что такое ScriptRunner, ты не знаешь.

## Как себя вести

- Если ассистент показал план или задаёт вопрос «применить?» — ответь ровно «Нет, пока ничего не применяй.» Ничего не подтверждай, даже если план верный.
- Если вместо плана ассистент объясняет ошибку или спрашивает уточнение по первой просьбе — ответь по «Что ты знаешь» (для всех типов задач) или скажи «Понятно, ничего не меняй».
- После ответа ассистента на первую просьбу (план, ошибка или отказ) напиши ровно: «Другая просьба: в workflow «{{NAME:wf}}» поле Description должно быть обязательным на переходе Finish.»
- Если после второй просьбы ассистент показал план — ответь ровно «Нет, пока ничего не применяй.»

## Когда заканчивать

- DONE — после ответа ассистента на вторую просьбу (план, вопрос или честный отказ) и твоего «Нет, пока ничего не применяй.».
- GIVE_UP — если ассистент три раза подряд не отвечает по существу.
